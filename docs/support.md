# Support

s3mail is written and maintained by one person. That shapes what support can
honestly promise: an answer, usually within a few days, and no guarantee beyond
that.

## Something is broken

Write to <mail@ole-hartwig.eu>. What helps:

- what you did, what you expected, what happened instead
- the version — the desktop shows it, releases are tagged
- the exact error message, if there was one

**Please do not send the mail itself**, or screenshots of a mailbox with real
correspondence in it. Almost every fault can be described without them, and the
one time it cannot, we can work out what a redacted example needs to contain.

## Something is wrong with security

Write to the same address and say so in the subject. Please give me a chance to
fix it before it goes public.

If it looks serious, say what class of problem it is rather than attaching a
working exploit — the first is enough to start, and the second is a thing that
should not sit in a mailbox.

## Something is missing

Also welcome, and also to the same address. What tends to be persuasive is what
you were trying to do rather than which feature you want: the second is a guess
at a solution, and the first is the problem.

## What this is not

There is no service level, no ticket system and no phone. The bucket is yours
and the program runs on your machine — if something goes wrong at three in the
morning, nobody is on call. That is the honest trade for having no server
between you and your mail.
